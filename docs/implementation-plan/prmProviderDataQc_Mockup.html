Grounded on real data. Each row = one PRM_CaseManagerAssociation__c record (its PRM_RequestType__c, plus the affected HealthcareFacilityNetwork / Address / HealthcareFacility it points to). In the QA org a single Terminate Current Office Information request fans out to as many as 285 network rows, and Remove Practitioner up to 92 — so even one "individual" request is a mass-verification job. Today QC has no before→after view (the "New" and "Existing" records are separate rows with cryptic names). This one component adds the diff, grouping, auto-checks and bulk verify/flag — identical for every request type and for true mass jobs.

SLDS reference mockup for prmProviderDataQc — one reusable QC verification component, grounded on real PRM_CaseManagerAssociation__c data pulled from the qa-sandbox org. Switch request types (top) to see the same grid + diff drawer handle office terminations, practitioner removals, address changes, panel-status and add flows. Click any row for the before→after detail.
