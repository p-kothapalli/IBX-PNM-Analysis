What needs to be ADDED to the report to match the guided flow

Adding these five predicates converts the report from a raw “at this stage” list into the flow’s actionable “truly ready & not yet decided” work list.

  • ADD
    PRM_Decision_Date__c equals blank Biggest driver — removes ~43 already-decided files (incl. all 42 denial cases).
  • ADD
    PRM_RoutineCommittee__c = true Restricts to routine committee only; excludes non-routine cases.
  • ADD
    Status not equal to Closed AND not equal to Additional Review Needed Removes returned / closed files that are no longer committee-ready.
  • ADD
    AccountId not equal to blank Drops orphaned case managers with no practitioner account.
  • ADD
    PRM_ProcessingStatus__c not equal to In Progress Excludes files still being processed by the async engine.

Decision needed: the report’s existing PRM_MedicalDirectorReview__c = 0 filter is not used by the flow. Today it removes 12 records that the flow would also drop for other reasons (0 net difference), but keep or remove it deliberately — it is a semantic divergence from the flow.

Cannot be matched by a report alone: the ReCred → Initial Cred population (PRM_ReCredentialing + PRM_CredentialingQC__c = true) requires the report’s record-type filter to be widened; a report locked to a single record type can never reproduce the flow’s OR condition. Consider a report type spanning both record types, or a formula/flag field.

Denials are decisions already actioned — they should not appear on a “ready for committee” work list. Adding the Decision Date filter removes all 42.

2. Does the report account for ReCred → Initial Cred? NO

The report’s record-type filter is locked to PRM_PractitionerParticipationRequest. The guided flow additionally pulls PRM_ReCredentialing records where PRM_CredentialingQC__c = true (recred cases converted into initial-cred credentialing). The report cannot surface these at all.

  • Converted records at Committee Review stage today: 1 (IA-0000042798).
  • It’s not in the flow right now only because it is RoutineCommittee = false, Status = In Progress, MedicalDirectorReview = true — but it is structurally the kind of record the flow is designed to include once ready.
  • The report will always show 0 of these regardless of readiness.

To account for them, widen the report’s record-type scope (report type spanning both) rather than a single-record-type report.

Reconciliation math

How the 497 base population splits between the two views.

Base: RecordType = PRM_PractitionerParticipationRequest AND Stage = 'Committee Review' = 497 REPORT = base − 12 (MedicalDirectorReview = true) = 485 FLOW = base − 12 (non-routine) − 46 (decided/denied, no account, etc.) + 0 (recred conv) = 439 Overlap (in both) = 439 Report-only = 46 Flow-only = 0 → flow ⊂ report The 46 report-only records = files the committee has effectively already actioned or that are not routine/ready: ~43 already have a Decision Date (incl. all 42 denials), remainder are non-routine / Additional Review Needed / no Account.
