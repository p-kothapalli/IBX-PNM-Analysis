🔍 Root Cause
A

B
All review flows filter by PRM_CaseManager__cPRMDRGetPractionerPracticeLocation and PRMExtractPracticeLocationToPractitionerFacility query WHERE PRM_CaseManager__c = PAR CaseManagerId — returns ZERO rows after PDM overwrote it.
C
False-positive error triggeredEligibleForUpdate COUNTQUERY sees PRM_Pending__c = true AND PRM_Active__c = false → assumes specialist deleted location → fires with Error = true.
D
Zero guard existsNo check at any point validates whether the practice location is still active before the specialist reaches the submit step.

Query Anchor
PractitionerId (AccountId)
Never overwritten by PDM. IndividualApplication.AccountId passed as PractitionerId to the DataRaptor.
Termination Signal
HealthcareFacility.PRM_EffectiveTo__c != null
Stamped only by formal termination flows (PDM, Provider Change, Account Term). Error records get EffectiveTo = null. Not affected by PDM CaseManager overwrite.
Component Classification
EffectiveTo != null AND PRM_Active = false
DR returns ALL HCPF rows. Component JS classifies: EffectiveTo stamped + Active = false = Terminated. De-duplicates by FacilityId before rendering.
