🚀 Application Review Redesign

From OmniScript to Tile-Based LWC Architecture

Solving the 4MB Payload Limitation

Executive Presentation • April 2026

🔴 The Problem

❌ "Save for Later" Fails with 4MB Payload

Business users frequently need to pause verification midway due to missing information. When they click "Save for Later," the system fails because the payload exceeds Salesforce's 4MB limit.

⏱️ Long Sessions

  • Application review takes 2-4 hours
  • Reviewers can't take breaks
  • Risk of session timeout
  • Lost work if browser crashes

🔒 All-or-Nothing Approach

  • Must complete entire flow at once
  • Can't resume from where left off
  • No visual progress tracking
  • Forces sequential completion
4,194,304 Character Limit (4MB) - OmniScript Constraint

🎯 Key Features

🎨

Visual Progress Tracking

Green checkmarks show completed tiles. Yellow warnings indicate issues. Real-time progress percentage.

🔄

Flexible Navigation

Complete tiles in any order. Jump between tiles freely. No forced sequence.

💾

Auto-Save Every 2 Minutes

Background auto-save prevents data loss. Never lose work due to session timeout.

⏸️

Resume Anywhere, Anytime

Close browser and resume later. Continue on different device. Session persists indefinitely.

🚫

No 4MB Limit

Each tile saves independently. Chunked data storage. No payload aggregation.

👥

Collaboration Ready

Multiple reviewers can work on different tiles. Audit trail for each verification.

📱

Modern UX

Responsive design. Modal-based verification. Clean, intuitive interface.

⚡

Performance Optimized

Lazy loading. Data loaded only when needed. Browser-based caching.

🔍

Enhanced Visibility

See what's verified vs pending. Warning badges for issues. Last modified timestamps.

⚖️ Pros and Cons Analysis

✅ PROS

  • Solves 4MB Issue: Completely eliminates payload limitation
  • Better UX: Modern, intuitive tile interface
  • Flexibility: Non-linear workflow
  • Resume Capability: Save and return anytime
  • Auto-Save: No data loss
  • Progress Tracking: Visual status indicators
  • Performance: Faster load times (lazy loading)
  • Scalability: Handles any data volume
  • Collaboration: Multi-user support
  • Reusability: Use for PSV, QC, ReCred flows
  • Audit Trail: Track who verified what and when
  • Maintainability: Modular, easy to update
  • Future-Proof: LWC is Salesforce's future

❌ CONS

  • Development Effort: 8-12 weeks initial build
  • Custom Objects: Need to create new objects for session tracking
  • Data Model Changes: Schema updates required
  • Testing Effort: Comprehensive testing needed
  • Training Required: Users need to learn new interface
  • Migration Period: Run both systems in parallel
  • Integration Updates: May need to update existing IPs
  • Browser Dependency: localStorage for temp data
  • Complexity: More components to maintain

⚠️ Mitigation Strategies

  • Phased rollout (pilot → full deployment)
  • Comprehensive training materials
  • Parallel run period with fallback
  • Reuse existing Integration Procedures
  • Hybrid storage (localStorage + DB)
