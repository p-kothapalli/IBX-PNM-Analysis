Mass Termination Scenario

Retiring a network — terminating 500 to 1,000+ relationships at once

When a healthcare facility network is retired, every provider linked to that network must be terminated on the same date. Today that means opening each record individually. With this capability, a PDA selects the network, sets one termination date, and the platform handles the rest — intelligently choosing the right processing method based on volume.

🔀 Smart Volume Routing — Automatic

PDA selects network(s) → sets Termination Date → clicks Terminate
↓
Under 500 Records
✅ Manual — In Screen
→ Preview list of affected providers
→ Confirm termination date
→ Process immediately in background
→ Email confirmation on completion
OR
Over 500 Records
⚙️ Mass-Load — Batch Queue
→ Queued as a background job
→ Processed in chunks — no timeout
→ Live status: Queued → Processing → Done
→ Email confirmation + failure report
Platform detects volume automatically — PDA uses the same screen for both paths

What this handles

✓
Single termination date applied to all records — set it once, applied consistently across every provider relationship
✓
Same Tax ID / NPI or mixed — works whether the network covers one group or hundreds of different providers
✓
Select one or multiple networks — retire several networks in one action if they share the same termination date
✓
Partial success — if any individual record fails, the rest still terminate. Failures are logged for Data Admin review

🔁 Reuse connection

The batch termination processor built for the "Terming Practitioners" operation (Wave 4) is the same engine used here — extended with a network-level selector and the smart routing switch. No separate system required.
